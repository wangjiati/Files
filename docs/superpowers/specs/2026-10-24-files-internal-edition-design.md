# Files 内部分支产品设计（精简版）

日期：2026-10-24
状态：已批准
基础上游：`files-community/Files`，起始提交 `ee399b0d3e09084aa24d7261c9342d92bc89a5da`

## 1. 产品定位

本产品是基于 Files 的独立内部分支，服务长期、大量管理文件的重度 PC 用户。重点不是改变外观，而是提供：

1. MSIX 安装版和真正可迁移的绿色便携版。
2. 全局、按列、按目录的时间格式设置，支持秒和毫秒。
3. 当前目录的列头筛选、多条件组合和正则表达式。
4. 完整只读 SQLite SQL 查询，文件结果与统计结果采用不同的合适视图。

产品暂时用于个人或团队内部，与原版 Files 并存，不向原版提交 PR。保留长期同步上游的能力，但不为首版增加复杂的分支治理和发布流程。

## 2. 已确认的产品边界

- 绿色版解压即可运行，配置和应用拥有的用户数据放在绿色应用目录下，整个目录复制到 U 盘或其他电脑后继续工作。
- 绿色版默认不注册文件关联、协议、后台任务、COM 或 Shell 集成；安装版保留这些能力。
- 两版核心文件管理功能一致，系统集成功能允许不同。
- 内部安装版默认不接管原版的系统集成功能。用户显式开启后才接管，界面显示当前状态，关闭或卸载时只恢复本产品修改的内容。
- 首版内部 MSIX 使用内部信任的证书签名，不连接 Files 官方更新地址，不建设更新服务器，通过内部发布包手动升级。
- SQL 支持完整只读 `SELECT`，包括子查询、CTE、聚合、窗口函数和连接，不退化为 SQL 风格条件生成器。
- SQL 结果不要求用户预先选择模式：能可靠映射到文件的结果可进入文件列表，统计及其他结果进入通用表格，原始结果不丢失。
- 首版至少支持 Windows x64，采用完整便携目录，不追求单个 EXE。

## 3. 目标与非目标

### 3.1 目标

- 同一套核心 UI 和业务代码支持安装与便携两种分发。
- 便携版不要求预装 .NET、Windows App SDK 或数据库运行时，不要求管理员权限。
- 便携版不静默把必要配置写入注册表或系统用户目录，也不依赖隐藏 MSIX/COM 注册。
- 时间格式规则清晰、可预览、即时生效，排序和筛选不受显示格式影响。
- 高级筛选统一处理列条件、正则、文件变化和异步取消。
- SQL 在安全只读边界内保留 SQLite 查询能力，并提供文件/表格双结果视图。
- 后续同步上游时，产品改动集中在明确接入点，避免无关重构造成冲突。

### 3.2 首版不做

- 便携版的文件关联、协议、后台任务、COM/Shell 集成和自动更新。
- 原版数据自动导入、安装版与便携版自动共享配置。
- 只读介质上的临时会话；数据目录不可写时明确报错。
- 递归扫描磁盘的当前目录筛选或 SQL 查询。
- SQL 写入、DDL、附加数据库、加载扩展和文件访问。
- 查询历史、保存查询、独立 schema 浏览器和复杂的管理界面。
- 任意嵌套布尔条件编辑器；复杂逻辑由 SQL 补充。
- SQL 增量镜像、缓存优化和未经性能证据支持的架构优化。

## 4. 分支与上游同步

采用三条简单规则：

1. 保留干净的上游跟踪分支，产品主分支独立，功能使用短生命周期分支。
2. 同步上游采用可审查的合并，不反复重写共享历史，不向上游提交 PR。
3. 内部发布时记录对应的上游提交；同步后验证两种构建及核心功能。

代码上优先新增独立服务、模型和 UI 组件，通过少量现有接入点组合。新业务代码不得继续扩散 `Package.Current`、`ApplicationData.Current` 等包身份访问。不做无关格式化、依赖升级或大规模重排。

首版不设置专门的上游同步演练门槛；首次实际需要同步时再验证分层和合并成本。

## 5. 安装版与绿色便携版

### 5.1 构建与平台差异

增加明确的 `Distribution` 构建维度：

- `Msix`：沿用应用清单、包身份和系统集成。
- `Portable`：`WindowsPackageType=None`，自带 .NET 和 Windows App SDK，输出完整 ZIP 解压目录。

正常差异优先通过现有依赖注入替换，条件编译只用于少量入口差异。首版只按实际需要建立两个边界：

1. **应用环境与数据位置**：版本、程序目录、设置/日志/缓存位置，以及包家族名的可选能力。
2. **系统集成**：安装版启用，便携版禁用；内部安装版的独占集成默认不接管。

更新和激活差异在现有入口处理，不为了架构完整额外建立一整套平台接口。

所有 `Package.Current`、`ApplicationData.Current` 和清单注册依赖需要审计。`Files.App.Server` 按功能拆分处理：核心文件管理所需能力提供非打包的进程内或普通本地进程实现，集成专属能力在便携版禁用。不得通过后台静默注册来复用现有 COM。

### 5.2 便携数据

默认数据根目录为应用目录下的 `Data`，内部按设置、日志、缓存等现有需要组织。具体文件格式由建造者选择，满足以下要求即可：

- 设置和用户数据有简单 schema 版本；写入使用临时文件和替换，避免中途失败损坏原文件。
- 缓存可以删除和重建，不能作为唯一事实源。
- 每个便携数据目录默认单实例；第二个实例明确提示，不设计复杂的多实例所有权系统。
- 数据目录不可写时明确提示，不静默回退到 `%LocalAppData%` 或注册表。
- 原版、内部安装版和不同便携副本的数据默认隔离，使用独立身份和目录。

Windows 自身产生的诊断或系统缓存不属于迁移承诺，但应用不能依赖这些位置保存必要数据。

### 5.3 路径与移动介质

首版采用简单规则：

- 普通目录规则保存规范化绝对路径。
- 可移动卷上的规则保存卷标识和卷内相对路径，使盘符变化后仍可匹配。
- 卷不可用时保留规则，不自动绑定到其他卷上的相同路径。
- 不为首版额外设计目录重命名追踪、重解析点全兼容或复杂冲突解决系统。

## 6. 时间列格式自定义

### 6.1 规则与优先级

支持以下优先级，从高到低：

1. 当前目录对特定列的规则。
2. 当前目录的默认时间格式。
3. 全局对特定列的规则。
4. 全局默认时间格式。

目录规则默认只对指定目录生效，创建时可选择“同时应用到子目录”。多条递归规则匹配时，距离当前目录最近的规则优先。每个作用域和列只保存一条有效规则，不引入额外冲突处理系统。

首版独立设置覆盖修改日期、创建日期和回收站删除日期。访问日期和 Git 日期的独立设置不阻塞首版。

### 6.2 格式与交互

- 提供日期、日期时分、日期时分秒、日期时分秒毫秒等预设。
- 提供自定义 .NET 日期时间格式和实时预览。
- 支持 `HH`、`mm`、`ss`、`fff`、12 小时制及当前区域性。
- 保留现有应用、系统和通用格式选项及默认行为。
- 非法格式在设置界面提示，不导致文件列表崩溃。
- 显示使用本地时间；排序和筛选始终使用原始 `DateTimeOffset`。
- 毫秒显示受文件系统和数据源精度限制，不承诺所有来源都有有效毫秒。

设置改变后只刷新受影响显示，不重新枚举文件。已打开目录立即生效，并检查列宽和截断。列级、目录级规则不能通过修改共享全局格式化器实现，以免不同标签或窗口互相串扰。

## 7. 高级筛选与正则

### 7.1 统一筛选管线

筛选作用于当前已加载目录项目，不重新枚举磁盘，不递归子目录。现有递归搜索保持独立，搜索结果也可继续经过可见投影。

统一数据流：

```text
完整已加载项目
  -> 不可变 DirectoryFilterSpec
  -> 后台求值
  -> 可见项目
  -> 现有排序、分组和 UI
```

现有顶部名称包含过滤映射为统一规范的一部分，列头和正则不维护互相覆盖的第二套状态。

使用一个执行上下文封装目录快照、筛选条件、源版本和取消令牌。旧任务不能覆盖新目录或新条件的结果。影响筛选字段的源变化统一触发合并重算，包括 watcher、重命名、大小/日期变化和首版实际使用的延迟属性。

### 7.2 列头筛选

在 `DataGridHeader` 增加独立筛选入口，保留点击列头排序。首版覆盖：

- 名称：包含、不包含、开头、结尾、等于。
- 类型、扩展名和标签：多选及明确的空值语义。
- 大小：比较和范围；未知大小不能视为 0。
- 修改和创建日期：自定义范围及常用相对区间，比较原始时间值。

不同列默认 AND，同一列多选默认 OR。活动筛选有明确标识和一键清除。切换目录默认清除临时筛选，不留下不可见条件。

路径、回收站扩展条件、Git/同步状态、高级 NOT 和任意条件树按后续需求增加，不作为首版门槛。

### 7.3 正则表达式

首版保留以下匹配目标：

- 完整物理文件名 `ItemNameRaw`。
- 当前显示名称。
- 完整路径。

同时提供大小写选项、语法错误提示、匹配超时和整体取消。默认目标在 UI 中明确，避免隐藏扩展名导致用户对结果产生误解。

实现要求：

- 每个求值任务只构造一次正则，普通包含匹配继续使用 `Contains`。
- 限制输入长度，设置匹配超时和整体执行取消。
- 不使用 `RegexOptions.Compiled`、运行时代码生成或无超时的回溯匹配。
- 正则错误、超时不导致应用崩溃，也不应用半份结果。

## 8. 只读 SQL 查询工作台

### 8.1 查询范围与快照

SQL 作用于当前已加载目录的只读快照。每次用户显式执行时建立私有 SQLite 内存快照，不在 UI 线程建表或查询，不在首版实现增量镜像。

至少提供：

- `files`：稳定 `file_id` 和可靠提供的名称、显示名、扩展名、路径、类型、字节大小、UTC 时间及基本标志。
- `tags`：标签定义。
- `file_tags`：文件与标签关系。

未知值使用 `NULL`，不使用显示文本代替数值或时间。回收站、Git、同步等字段只在能可靠提供时加入，不为扩充 schema 阻塞首版。

### 8.2 完整只读 SELECT 与安全

支持 SQLite 只读查询，包括子查询、`WITH`/`WITH RECURSIVE`、聚合、`HAVING`、窗口函数、连接、集合操作、计算列和安全内置函数。

“完整 SQL”指完整只读 `SELECT`，不包括数据库管理或文件系统访问。必须同时落实：

- 私有内存快照，不暴露真实设置或标签数据库。
- SQLite authorizer 和单语句验证。
- 禁止写入、DDL、多语句、`ATTACH`/`DETACH`、扩展加载、危险 PRAGMA 和文件读写函数。
- 后台执行、可取消、超时和最大结果数。
- 达到限制或截断时明确提示，不能静默声称结果完整。
- 进度/中断机制与取消联动，旧查询不能覆盖新目录结果。
- UI 自动生成的值使用参数化查询。

不能只靠正则检查 SQL 或只读连接字符串来充当安全边界。

### 8.3 文件与表格双结果

所有查询先保留通用表格结果，再根据结果结构识别文件视图能力：

- 每行包含有效 `file_id` 且能映射到当前快照时，提供文件列表视图。
- 聚合、统计、仅计算列、缺少有效文件 ID 或无法可靠映射的结果显示通用表格。
- 可映射结果默认进入文件列表，同时可切换查看原始表格和计算列，不要求用户预先选择查询类型。
- 多行映射到同一文件时，文件列表按 `file_id` 去重，原始表格保留所有行。
- 文件视图保留 SQL 的结果顺序；无 `ORDER BY` 时不承诺额外顺序。用户手动排序只改变当前视图，不回写 SQL。
- 文件视图支持现有选择、打开、复制等核心操作。
- 源目录改变后，已有结果明确标记为快照；刷新需要显式重新执行。

### 8.4 首版查询界面

首版只提供实用功能：查询编辑器、字段说明、少量示例、执行/取消、错误信息、耗时、文件/表格结果视图。查询历史、保存查询和独立 schema 浏览器推迟到实际使用反馈后。

## 9. 四个交付阶段

### 阶段 1：双版本基线

- 建立产品分支和 `Msix`/`Portable` 构建。
- 完成最小非打包启动和自包含运行时验证。
- 实现便携数据目录、应用身份和核心 Server 替代。
- 便携版禁用系统集成，内部安装版默认不接管独占集成。
- 验证干净系统、非管理员、U 盘、数据移动、单实例和双版本共存。
- 配置内部签名和手动发布，不连接官方更新源。

### 阶段 2：时间格式

- 实现全局、按列、指定目录及可选递归规则。
- 完成预设、自定义格式、预览、毫秒和即时刷新。
- 验证优先级、盘符变化、排序和列宽。

### 阶段 3：高级筛选

- 统一名称过滤、执行上下文和源变化重算。
- 实现首版列头条件、活动状态和清除。
- 实现完整文件名、显示名称、完整路径的正则匹配及安全执行。

### 阶段 4：SQL 与内部发布

- 实现内存快照、只读 schema 和安全执行器。
- 实现完整只读 SELECT、文件/表格双结果和必要错误提示。
- 产出 MSIX 与便携 ZIP，记录上游基线和必要升级说明。

## 10. 首版验收

### 双版本

- 干净 Windows 环境未安装额外运行时，便携版可以启动。
- 非管理员从普通目录和 U 盘运行；移动目录和改变盘符后配置可用。
- 便携核心功能不依赖 MSIX/COM 注册，必要应用数据不静默写入系统目录。
- 原版、内部安装版和便携副本并存时身份与数据不互相覆盖。
- 内部安装版默认不接管独占集成，手动更新不访问官方更新源。

### 时间

- 全局、按列、目录规则的优先级和可选递归符合设计。
- 秒、毫秒、12/24 小时制、区域性和非法格式行为正确。
- 设置即时刷新，排序仍按原始时间，可移动卷规则在盘符变化后可匹配。

### 筛选与 SQL

- 大目录中 UI 不被阻塞，旧任务可取消且不覆盖新结果。
- 重命名、watcher 和首版筛选字段变化后结果正确。
- 三种正则匹配目标、大小写、错误和超时行为正确。
- 子查询、CTE、聚合、窗口函数和连接按 SQLite 语义工作。
- 写入、DDL、多语句、ATTACH、扩展和危险 PRAGMA 被拒绝。
- 文件结果可执行核心文件操作，统计结果完整显示在表格中；截断和资源限制明确可见。
- 普通目录、搜索结果、回收站及一种代表性非本地存储执行针对性冒烟验证。

## 11. 建造者可自行决定

- 服务和模型的具体命名、少量接口拆分及 XAML 布局。
- 便携设置和标签的文件格式。
- 核心 Server 替代采用进程内还是普通本地进程。
- 正则和 SQL 的具体数值限制，通过基准和取消测试确定并向用户可见。
- 内部产物名称、证书和包身份，只需与原版隔离并满足内部签名发布。

不得自行改变真正目录便携、时间规则层级、正则三种匹配目标、完整只读 SELECT、文件/表格双结果或独立分支这些产品边界。
