# 批量重命名（Batch Rename）设计

日期：2026-11-01
状态：待用户批准
视觉参考：`.superpowers/brainstorm/284-1793510410/content/layout-v7.html`（高保真交互原型，v1～v7 为迭代历史）

## 1. 背景与意图

Files 现有的多选 F2 只会打开 `BulkRenameDialog`——"全部改成同一名字 + 自动去重"，除此之外没有任何批量重命名能力。用户的主要场景是**批量改照片名和日志名**：本质上是"以文件名和扩展名为对象的查找替换"，即文本编辑器 Ctrl+H 的文件系统版。

参考对象是 PowerToys 的 PowerRename，但要修正它的两个根本问题：

1. **交互反模式**：互斥选项（纯文本 vs 正则、仅文件名 vs 仅扩展名）与可叠加选项（匹配全部、区分大小写、包含文件/文件夹/子文件夹）全部做成图标切换按钮，外观是按钮、行为是勾选框，看不出哪些互斥哪些可叠加。
2. **界面空间不足**：小弹窗、列有限、不可放大，预览和规则挤在一起。

竞品调查（Directory Opus、Total Commander、XYplorer、OneCommander）验证了本设计的结构：Directory Opus 的 Advanced Rename 与本设计几乎同构（预设侧栏 + 规则区 + 带勾选的预览 + 手改标红锁定）；Total Commander 用名称/扩展名分离掩码防止误伤扩展名；XYplorer 提供文件夹名变量与冲突策略开关。本设计 additionally 提供了所有竞品都没有的**子文件夹深度限制**。

## 2. 目标 / 非目标 / 反目标

### 目标（v1）

- 查找替换：文本 / 通配符 / 正则三种互斥模式；匹配全部或仅第一处；区分大小写
- 应用到：仅文件名 / 仅扩展名 / 全部（互斥），默认仅文件名
- 方案模板：查找替换、开头追加、结尾追加（互斥选择，参数化快捷方式）；编号/日期作为模式串预设按钮（见 §5）
- 作用域：仅选中项 / 当前文件夹 / 含子文件夹（互斥）+ 深度 1–9 步进器 + 包含文件/文件夹
- 变量：计数器 `${start|increment|padding}`、文件日期时间 `$YYYY…`、文件夹名 `${folder}`、正则捕获组 `$1…`
- 大小写转换：不变/全小写/全大写/首字母/每词首字母，作用于替换结果
- 预览列表：改前/改后对照 + 位置列 + 按文件夹分组 + 行内红删绿增差异；每行勾选；双击改后格逐项手改（打"手动"标签，规则变化不覆盖）；全部/将改动/加序号三段筛选 + 结果内搜索；虚拟滚动
- 冲突策略：自动加序号（默认）/ 跳过 / 覆盖（二次确认，旧文件入回收站）
- 预设：保存/加载命名方案（模板+参数+作用域+大小写），不含手改值
- 剪贴板：按行复制改前名称；按行粘贴新名称（空行=跳过该行，粘贴值标"手动"）
- 入口：多选 F2；右键菜单"批量重命名"
- 界面：大尺寸弹窗（默认约主窗口 85%）、可最大化/还原；规则栏固定一侧默认右侧、可切换到左侧（位置记忆）
- 撤销：整批一次 Ctrl+Z

### 非目标（v1 明确不做）

- EXIF / 拍摄日期变量（用户已确认推迟）
- 随机字符串 / UUID 变量
- 多步规则链（TC 的 F5 "next step"）
- 计数器拖拽调序、字母计数器
- 改名同时移动文件（XYplorer 的 `\`）
- Boost.Regex（使用 .NET 正则）

### 反目标（做了就算失败）

- 互斥选项用切换按钮/普通按钮呈现（PowerRename 的病）
- 规则面板遮挡预览结果
- 无预览直接执行、或静默覆盖无确认
- 弹窗不可放大、长列表卡顿

## 3. 入口

| 入口 | 行为 |
|---|---|
| 多选 + F2 | 打开批量重命名弹窗（替换现 `BulkRenameDialog` 的多选分支），默认作用域=仅选中项 |
| 选中项右键菜单"批量重命名…" | 同上；选中 ≥2 项时显示 |
| 空白处右键菜单"批量重命名…" | 打开弹窗，无需预先选择；有选中项时默认=仅选中项，否则默认=当前文件夹 |
| 顶部工具栏"批量重命名"按钮 | 常驻可用；默认作用域规则同空白处右键 |
| 单选 + F2 | 保持现有内联编辑不变 |

默认作用域规则一句话：**有选中项就默认"仅选中项"，没有就默认"当前文件夹"**（用户随后可在作用域卡片里改）。

## 4. 界面结构（弹窗）

```
┌──────────────────────────────────────────────────────┐
│ ✏️ 批量重命名   路径 · 作用域摘要 · 对象数   [⇄规则栏][⬜][✕] │ ← 标题栏（⬜=最大化/还原）
├───────────────────────────────┬──────────────────────┤
│ 预览区（左，弹性）                │ 规则栏（右，300px 固定）  │
│ ① 工具行：三段筛选+计数 · 剪贴板 ·  │ [预设 ▾][＋存当前为预设]  │
│    结果内搜索                     │ [方案模板] 三枚胶囊(互斥)  │
│ ② 列表：勾选|位置|改前|改后        │   └ 模板参数区(随胶囊切换) │
│    按文件夹分组 · 差异高亮 · 手改/  │ [作用域] 单选+深度+包含   │
│    加序号/未改动 状态              │ [变量与格式] 计数器/日期/  │
│ ③ 底部：冲突提示 · 策略 · 统计 ·    │   ${folder}/大小写       │
│    取消/应用                      │                      │
└───────────────────────────────┴──────────────────────┘
```

- 弹窗默认尺寸约为主窗口客户区的 85%；提供最大化/还原；停靠侧持久化到设置。**不做边缘拖拽缩放与尺寸记忆**（实用优先裁决：覆盖场景只需"够大 + 可最大化"）
- WinUI 的 `ContentDialog` 不支持最大化——实现须用自定义覆盖层或 `AppWindow`（见 §12 建造者决定）
- 原始视图不被占用：弹窗关闭即恢复，无任何残留状态

## 5. 方案模板（互斥胶囊）

模板是参数化快捷方式，切换时**保留作用域、大小写设置和所有手改值**：

| 模板 | 参数 | 语义 |
|---|---|---|
| 查找替换 | 查找、替换为、模式（文本/通配符/正则）、应用到、匹配全部、区分大小写 | 核心，见 §6 |
| 开头追加 | 前缀文本；☐跳过已含此前缀的名称 | 等价正则 `^` → 前缀 |
| 结尾追加 | 后缀文本；☑插入在扩展名之前 | 勾选：`img.jpg→img_备份.jpg`；不勾：`img.jpg→img.jpg_备份` |

**编号/日期不是模板**（实用优先裁决）：它们只是"模式串预设"按钮（在变量与格式卡），一键把 `照片_${padding=3;start=1}` / `$YYYY-$MM-$DD_${padding=3}` 填入"替换为"，随后可自由编辑；扩展名保护由"应用到=仅文件名"承担。

大小写转换与变量按钮对所有模板生效（在模板结果上再做整体变换）。

## 6. 查找替换规则

- **模式（互斥分段控件）**：
  - 文本：字面量查找替换；同样展开变量（见 §7）
  - 通配符：`*` 任意串、`?` 单字符，转内部正则实现（参考 `BaseQueryResults` 的转换思路）
  - 正则：.NET `Regex`，ECMAScript 兼容子集；替换值支持 `$1…$9` 捕获组引用；构造必须带 `MatchTimeout`（参考 `DirectoryRegexFilter`）
- **应用到（互斥）**：仅文件名（默认）/ 仅扩展名 / 全部
- **可叠加复选框**：匹配全部（否则仅第一处）、区分大小写

## 7. 变量语法（v1）

| 家族 | 语法 | 说明 |
|---|---|---|
| 计数器 | `${}` `${start=N}` `${increment=N}` `${padding=N}`，可在单花括号内组合 `${start=10;padding=4;increment=2}` | 序号按预览列表当前排序分配；同一替换串允许多个计数器，按出现位置各自独立递增 |
| 日期时间 | `$YYYY $YY $Y $MMMM $MMM $MM $M $DDDD $DDD $DD $D $hh $h $mm $m $ss $s $fff $ff $f` | 与 PowerRename 兼容的记法；来源为该项的创建或修改时间（按日期模板选择；查找替换模板中默认创建时间） |
| 文件夹名 | `${folder}` | 直接父文件夹名（不含路径），如 `大阪\夜景\DSC_0001.jpg` → `夜景` |
| 捕获组 | `$1…$9` | 仅正则模式；需勾选"匹配全部" |

**展开规则（我的决定，用户可推翻）**：变量在所有模式下始终展开（利于发现性）；v1 不提供字面量转义（需求罕见，记入后续候选）。

## 8. 作用域

- 单选（互斥）；**仅当前选中的作用域显示实时计数徽标**（异步统计，可取消；实用优先裁决：不为未选中的作用域枚举全树）：
  - 仅选中项（默认）——右键入口天然对应此项
  - 当前文件夹——按当前文件列表排序全部对象
  - 含子文件夹——枚举子目录并受深度约束
- 深度步进器：1–9（默认 2；我的决定），提示文案"含第 1–N 层"
- 包含：☑文件（默认开）、☐文件夹（默认关，开时文件夹本体可重命名）
- 作用域含子文件夹时，预览列表显示位置列并按文件夹分组；目标可能不在当前视图内，执行按完整路径处理
- 网络盘/云目录枚举慢：计数与列表异步渐进填充，不阻塞 UI

## 9. 预览列表

- 列：勾选框 | 位置（相对路径，仅多文件夹时显示）| 改前 | 改后
- 行状态：
  - 将改动（改后列加粗，行内红删绿增差异高亮）
  - 手动（打"手动"标签；规则/模板/预设变化不覆盖；行内 ✓ 确认 / ✕ 放弃 / ↺ 重置此行）
  - 将加序号（冲突且策略=自动加序号，直接显示加序号结果如 `京都_2053 (2).jpg`）
  - 已跳过（冲突且策略=跳过）
  - 未改动（灰显 + 原因标签：不匹配 / 未包含文件夹；默认参与勾选可手动勾上强改？——否：勾选框=是否参与本批重命名，未改动行的勾选含义见下）
- 勾选框语义：该行是否参与执行（沿用 PowerRename/Opus 模型）；未勾选行灰显；未改动行的勾选与否无实际效果（无改动可执行）
- 筛选：全部 / 将改动 / 加序号（含跳过）三段 + 计数徽标；结果内搜索（对改前/改后/位置模糊匹配）
- 虚拟滚动（千级对象不卡）
- 双击"改后"单元格进入行内编辑（TextBox + ✓/✕）

## 10. 冲突与策略

- 冲突判定：大小写不敏感（Windows 语义）；同批内多名同目标 与 目标已存在文件 均算
- 大小写-only 变化（`img.jpg → IMG.jpg`）不算冲突，执行时需按 case-rename 处理（避免"目标已存在"误报）
- 策略（底部下拉）：
  - 自动加序号（默认）：Windows 习惯 `名称 (2)`；预览直接显示结果
  - 跳过：执行时跳过并汇总提示
  - 覆盖：应用前二次确认；被替换文件移入回收站。**确认框明示"被覆盖文件无法通过撤销恢复"**；整批撤销只还原重命名本身（实用优先裁决：不做"删除+重命名合并撤销单元"）
- 选择策略后"应用"不再被冲突禁用（有策略即有解）
- 覆盖的实现注记：现有 `RenameAsync(NameCollisionOption.ReplaceExisting)` 是不可撤销的永久替换，不符合语义；实现采用"先删入回收站，再重命名"，撤销只回放重命名
- 行级非法名称（非法字符/保留设备名/为空/超长 255）：行标错并阻止该行执行，不阻塞整批

## 11. 预设 / 剪贴板 / 应用与撤销

- **预设**：规则栏顶部"预设 ▾ / 存当前为预设"；保存模板+参数+作用域+深度+大小写；不保存手改值；可命名、删除；持久化到应用设置
- **剪贴板**：
  - 复制改前：按当前列表顺序每行一个名称（含相对路径可选——我的决定：不含路径，仅名称）
  - 粘贴新名称：按行读入赋给"改后"并标"手动"；空行=跳过该行；行数多于对象时截断并提示；配合表格/文本编辑器使用
- **应用**：底部主按钮；执行走现有 `FilesystemHelpers.RenameAsync`（逐项、带撤销历史）；进度在按钮区内联呈现（不新弹窗）；单项失败不中断整批，结束汇总失败清单；成功后关闭弹窗并刷新视图
- **撤销**：整批为一次 Ctrl+Z 单元（若现有历史机制不支持合并，按逆序逐项撤销，对用户呈现为一个动作）；覆盖策略下被覆盖的文件不随撤销还原（见 §10）

## 12. 实现约束与指引（Files 代码库）

- 入口：`src/Files.App/Actions/FileSystem/RenameAction.cs` 多选分支；`src/Files.App/Data/Factories/ContentPageContextFlyoutFactory.cs` 的**选中项菜单**与**空白处菜单**各加一项"批量重命名…"；顶部工具栏加常驻按钮（沿用现有工具栏/命令注册模式）
- 替换/重构 `src/Files.App/Dialogs/BulkRenameDialog.*` 与 `src/Files.App/ViewModels/Dialogs/BulkRenameDialogViewModel.cs`；弹窗注册在 `src/Files.App/Services/App/AppDialogService.cs`
- 执行与校验：`IFilesystemHelpers.RenameAsync`、`FilesystemHelpers.IsValidForFilename`；ADS（`AlternateStreamItem`）重命名兼容沿用现有路径
- **可最大化的弹窗**：`ContentDialog` 做不到。倾向在主窗口内做自定义模态覆盖层（Chrome 自绘：标题栏、最大化/还原），生命周期挂主窗口；备选 `AppWindow` 独立窗口（失去模态性）——建造者决定并给出理由
- 正则：`System.Text.RegularExpressions.Regex` + `MatchTimeout`（参考 `DirectoryRegexFilter`）；通配符→Win32 表达式转换参考 `FolderSearch` 使用的 `FileSystemName.TranslateWin32Expression`
- 列表：`ItemsRepeater`/`ListView` 虚拟化；分组用 `CollectionViewSource` 或自定义分组模型
- 本地化：全部用户可见字符串入 `src/Files.App/Strings/en-US/Resources.resw`（`Strings.Xxx` 由 generator 生成）；XAML 用 `{helpers:ResourceString}`
- 设置：停靠侧、上次预设名挂现有 settings service（如 `UserSettingsService` 模式）；弹窗不记忆尺寸
- UI 控件：互斥=分段控件/单选；叠加=CheckBox；图标用 Fluent 线性图标；遵守 `.editorconfig` 与 CRLF

## 13. 键盘

| 键 | 行为 |
|---|---|
| Ctrl+H | 聚焦"查找"输入框。**弹窗打开期间覆盖全局绑定**（现有 `Ctrl+H` = 显示/隐藏隐藏项），关闭弹窗后立即恢复——实现需要弹窗作用域的键盘加速器抑制（与 §14.1 的弹窗实现方式联动：主窗口覆盖层必须显式处理，`AppWindow` 天然隔离） |
| Enter | 应用（焦点在列表编辑框时为确认该行） |
| Esc | 关闭弹窗（编辑态先退编辑）；未应用的改动直接丢弃，不弹确认 |
| F2 | 列表内逐项手改下一行（进入编辑） |
| 双击 | "改后"单元格进入编辑 |

（Esc 不确认即关：未发生的重命名无法也无需撤销，多一层确认只会烦人——我的决定，可推翻。）

## 16. 决策记录（用户已定）

- 形态：弹窗（非双窗格接管）；列表弹窗 + 规则区同屏
- 入口四个：多选 F2、选中项右键（≥2 项）、空白处右键、顶部工具栏按钮；有选中默认"仅选中项"，无选中默认"当前文件夹"
- 规则栏默认右侧、可切左侧；宽 300px
- 通配符模式必须支持
- v1 含：大小写转换、计数器、日期变量（仅创建/修改时间）、逐项手改、方案模板（开头/结尾追加等）、作用域+子文件夹深度、冲突策略、预设、剪贴板名称、可最大化弹窗
- EXIF/拍摄日期、随机串推迟
- UI 纠错原则：互斥用分段/单选、叠加用复选框，绝不复刻 PowerRename 的切换按钮反模式
- 实用优先裁决（审查过度设计后）：砍边缘拖拽缩放与尺寸记忆（只留最大化/还原）；方案模板减至 3 枚，编号/日期降级为模式串预设按钮；覆盖策略不承诺撤销还原；作用域计数只显示当前选中项；手动行重置仅 ↺ 一个入口
