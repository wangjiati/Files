# 全视图筛选（Filter in All Views）— 交互设计

日期：2026-11-14
状态：待评审（1:1 原型已交付）
原型：`docs/prototypes/filter-all-views/index.html`（浏览器直接打开，1:1 还原 Files / WinUI 3 视觉与控件尺寸，全流程可点击）

## 1. 意图与背景

用户诉求：列筛选目前只能在详细视图下使用；筛选（文件名、修改时间、创建时间、大小、扩展名、文件类型）应在所有视图下可用。

现状（代码事实）：

- 筛选引擎本身视图无关：`ShellViewModel.DirectoryFilter`（`DirectoryFilterSpec` / `DirectoryFilterEvaluator`，位于 `src/Files.App/Utils/Storage/Filtering/`）已支持名称（含正则）、类型/扩展名、标签、大小区间、日期区间、含空值。
- 入口 1（仅详细视图）：`DetailsLayoutPage` 列头 `DataGridHeader` 的筛选按钮 → `DirectoryFilterFlyout`。
- 入口 2（全部视图但仅名称）：工具栏漏斗开关 `ToggleFilterHeader` → `ModernShellPage.FilterHeader` 行（"筛选:" + 180px 文件名 AutoSuggestBox，绑定 `FilesAndFoldersFilter` 字符串）。
- 两套机制互不相通：`FilesAndFoldersFilter` 与 `DirectoryFilterSpec` 是两个真相。

## 2. 设计总览：一套模型，两种模式

**目标用户（设计基线）**：重度资源管理器用户——一切决策以键盘效率、组合能力、信息密度优先；可发现性让位给 tooltip 与教学层。

改造点选在用户已发现的地方：**把 FilterHeader 从"仅文件名"升级为全维度筛选栏**，并统一筛选模型（`DirectoryFilterSpec` 是唯一真相）。

1. **统一入口**：沿用工具栏漏斗按钮（访问键 F），增设 `Ctrl+Shift+F`。按钮显示/隐藏筛选栏；筛选生效时按钮保持点亮；筛选栏被收起但筛选仍生效时，按钮右上显示活动圆点（与列头 `FilterActiveDot` 同一语言）。
2. **筛选栏（改造后的 FilterHeader，两种模式）**：保留原骨架（文件夹缩略图，Padding 26,8,12,8 不变）。**最前为 [常规 | 高级] 分段切换（默认常规）**：
   - **常规 = 纯搜索框**：名称框支持**多关键字**（空格或逗号分隔，需同时满足）与 **Windows 通配符**（`*` 任意串、`?` 单字符，整名匹配、忽略大小写，**按完整文件名匹配**——不受"隐藏扩展名/快捷方式无扩展名"影响）；**不提供"添加"按钮与条件列表**；高级设置的条件不参与常规求值。
   - **高级 = 完整能力**：名称条件与全部追加条件在**同一行内流动、共用完全相同的一套控件**（30px 高、13px 字号、同款边框/开关/移除按钮）：`[维度名][Aa][.*][.ext][运算符▾][输入框][×]`——**Aa = 区分大小写**；.* 切换正则；**.ext = 作用域**（点亮 = 完整文件名含扩展名，不点亮 = 显示名称不含扩展名）；三者对文本/正则**通用**；**追加的"名称"条件同样具备这三个开关**。 **运算符 12 个**：包含/不包含、开头是/开头不是、结尾是/结尾不是、等于/不等于、**长度大于/长度小于/长度等于/长度不等于**（长度类选中时输入框切换为数字输入，按作用域字段计字符数）。
   - 两套配置**互不丢失**；整行宽度用满后才在条件边界换行，＋添加 始终贴住最后一个条件。
3. **条件列表 + 并且/或者连接符（展开式控件组，即时生效）**：`添加` 菜单顶部选择连接符（[并且添加 | 或者添加]），每次点击追加一条**展开的条件控件组**（同维度可重复；入列为草稿并自动聚焦首个控件）。**每条追加条件（含第一条）始终显示 并且/或者 连接符**，与视觉上始终存在的名称组关联；暂无可连接的前置条件时呈弱化态，填入名称后即刻生效。七个维度：名称、类型、**扩展名（独立维度）**、修改日期、创建日期、大小、文件标签。**控件组形态**：类型/扩展名/标签 = 值令牌（单删，>5 折叠 +N）+ `＋` 复选选择器（多选即时、保持打开）；**日期 = 预设下拉，预设按当前时间动态计算区间**：所有日期 / **最近 1 小时 / 最近 6 小时 / 最近 24 小时** / 今天 / 昨天 / 最近 3 天 / 最近 7 天 / 最近 30 天 / 本月 / 今年，选"自定义…"就地展开 从/至；大小 = `min [单位▾] – max`；名称 = `[Aa][.*][.ext]` + 运算符 + 输入框（长度类运算符时切换数字输入；正则非法红框）。**全部即时生效，无"应用"按钮**；**编辑器复用现有 `DirectoryFilterFlyout` 内的面板**（提取为内联编辑器，不重写控件）。**求值：AND 优先结合**（A 并且 B 或者 C = (A∧B)∨C）；括号分组不做 UI——复杂嵌套逻辑归正则。**列头入口 = 弹窗（保持原有交互）**：点击任一列头在列头下方弹出该维度的筛选弹窗，弹窗内使用与筛选栏相同的条件编辑器与查询语言（名称列头同样具备 Aa/.*/.ext 与 12 运算符）；点“应用”把条件加入筛选栏的条件列表并切到高级，点“清除”移除该列条件，点“清除所有筛选”重置全部；不再向筛选栏直接追加草稿。
4. **搜索子文件夹（递归）+ 深度控制**：筛选栏内联复选框（作用域开关，清除筛选时保持），旁附**深度下拉：默认 2 层，可调 1/2/3/5/不限（常规/高级共用）**。**递归是匹配范围而非显示方式：仅在筛选生效时**将子目录项目纳入匹配——未筛选时勾选不改变视图，避免"勾选即全量平铺"的递归爆炸。生效时扁平视图（详细/列表/卡片/网格）参与匹配，详细视图自动出现"位置"列，卡片副行与其余视图 tooltip 显示相对路径；列视图按栏浏览、不递归；状态栏计数附"（含 N 层子文件夹）"。真实实现要求惰性枚举、进度反馈、可取消。
5. **跨视图持久**：切换 5 种视图（详细/列表/卡片/网格/分栏）筛选不丢；列视图中筛选作用于每栏所在目录。
6. **空结果态**：**复用现有空态文案 `NoSearchResultsFound`**（"没有与搜索条件匹配的项"，语义一致，不新增文案）+ 清除按钮；状态栏显示"已显示 N / M 个项目"。

非目标：不改变筛选引擎语义；不做保存的智能筛选/自定义视图；不覆盖搜索框职责。

反目标（做错即失败）：出现两套筛选真相；详细视图列头行为回退；筛选状态在任何视图下不可见。

## 3. 关键交互细节

- **常规**：名称框多关键字（空格/逗号分隔，AND）与通配符 `*`/`?`（整名匹配、忽略大小写）；无添加与条件列表；高级条件不参与常规求值。
- **常规/高级切换**：两套配置互不丢失；切回高级恢复 12 个运算符、连接符与正则作用域。
- 名称框输入 → 即时筛选（与现 `UpdateSourceTrigger=PropertyChanged` 一致）；Enter 立即确认并重新投影。
- 长度类运算符（大于/小于/等于/不等于）选中时，输入框切换为数字输入，值非法（空/非数字）按未生效处理。
- 选择器：勾选即时生效且保持打开（连续多选），令牌在条件组内单删，>5 折叠 +N。
- 日期预设（所有日期 / 最近 1 小时 / 6 小时 / 24 小时 / 今天 / 昨天 / 最近 3 天 / 7 天 / 30 天 / 本月 / 今年）= 按**当前时间动态计算**区间（小时级预设需时间精度，对应引擎 `MinDate`/`MaxDate` 的 `DateTimeOffset`）；选"自定义…"就地展开按天粒度的 从/至。
- 大小筛选不含文件夹项（与现引擎 `MatchesSize(null)` 行为一致）。
- **列头与筛选栏同源**：任一列头点击 = 追加同维度条件（名称列头含 Aa/.*/.ext 与 12 运算符）；常规模式下点击列头自动切到高级。
- 递归：仅筛选生效时参与；深度默认 2 层、可调 1/2/3/5/不限；未筛选时勾选不改变视图。
- 条件即时生效，无"应用"按钮；未生效草稿以控件虚线框呈现。
- 首个生效条件前不显示无意义的"并且/或者"连接符；高级模式的条件列表非空且名称条件未生效时，空的名称编辑器收起，名称列头筛选直接写入该名称编辑器。
- Esc 逐层关闭弹出层；外部点击关闭全部弹出层。
- 键盘：条件控件 / 添加 / 列头筛选均为可聚焦控件；`Ctrl+Shift+F` 显示筛选栏并聚焦名称框。

## 4. 设计决策（本人决定，可推翻）

| # | 决策 | 理由 |
| --- | --- | --- |
| D0 | 人设基线：重度资源管理器用户 | 效率/组合性/密度优先；可发现性让位 |
| D1 | `FilesAndFoldersFilter`（字符串）并入 `DirectoryFilterSpec` 名称维度 | 消除两套真相；地址栏编码（`DirectoryFilterAddress`）天然继承 |
| D3 | 空态复用现有 `NoMatchingItems`（"没有与筛选条件匹配的项"），不新增文案 | 语义一致、文案更贴切；少一个资源键、少一处翻译 |
| D4 | 筛选栏允许在筛选生效时被收起（按钮出圆点） | 尊重屏幕空间；状态不丢、可一键找回 |
| D5 | 高级模式名称维度完全内联（零弹层），输入框为单一关键字/短语 | 组合逻辑统一由条件列表（并且/或者）承担；常规模式另有多关键字+通配符语法（D9） |
| D6 | **Aa = 区分大小写**、**.ext = 作用域**（完整文件名/显示名称），同为图标开关、文本与正则通用；去掉"完整路径"目标 | 二态用开关表达，三个开关（Aa/.* /.ext）同族同构；两套模式一份语义；按路径筛选不属于名称维度。**实现：Aa 已落地（文本/通配按 Ordinal/OrdinalIgnoreCase 切换）；正则目标只保留完整文件名/显示名（`FullPath` 枚举保留用于旧地址解码，UI 不再提供）** |
| D7 | **条件列表 + 并且/或者连接符**：AND 优先结合，同维度可重复；**条件为展开控件组、即时生效（无应用按钮、无摘要药丸）** | "添加即组合 + 所见即所筛"；摘要药丸隐藏真实条件，展开控件让每条条件可直达编辑。选择类取反（是/不是）列为 P2 备选，首版不做 |
| D8 | **搜索子文件夹**为作用域开关：仅在筛选生效时参与匹配（未筛选不平铺显示），清除筛选时保持；**深度默认 2 层可调（1/2/3/5/不限）**；列视图不递归 | 防递归爆炸（真实目录可达数万项）；默认 2 层覆盖多数场景又可控；递归是范围不是条件；列视图是浏览模型 |
| D9 | **常规/高级切换**（默认常规）：常规 = 纯搜索框（多关键字空格/逗号分隔 + Windows 通配符 * ?，无添加/条件）；高级 = 完整能力；两套配置互不丢失 | 兼顾快速筛选与重度用户表达力；常规不暴露条件模型、高级不牺牲表达力。实现上只是 UI 状态（关键字串 + 条件集合），任一时段仅一个投影到 spec |
| D10 | **列头 = 弹窗，应用后进入筛选栏条件列表**：弹窗复用筛选栏的条件编辑器与查询语言；“应用”把条件加入条件列表（自动切高级），“清除”移除该列条件，“清除所有筛选”重置 | 保持用户熟悉的列头弹窗交互；查询语言与筛选栏完全一致，筛选状态仍只有一份（条件列表） |
| D11 | **时间预设含小时级**（最近 1/6/24 小时、今天、昨天、3/7/30 天、本月、今年），按当前时间动态计算；自定义按天 | 小时级是重度用户高频（"刚刚下载/改过的"）；动态计算避免预设过期 |
| D12 | **复用优先的架构**：引擎原位扩展；条件模型复用 `DirectoryFilterViewModel`；编辑器复用现有 Flyout 面板；投影复用 `ScheduleFilterProjection` | 新增代码只落在必要的 UI 协调与引擎扩展，避免平行实现两套筛选交互与两套状态 |

## 5. 开放问题（需产品/实现确认）

- 列视图每栏为独立 Shell 页：筛选"随栏继承"（本原型行为）还是"仅最右栏生效"？递归在列视图不生效（浏览模型）。
- 递归结果的分组/排序策略（是否按位置分组）与地址栏编码（`DirectoryFilterAddress` 是否携带递归标志与位置列偏好）。
- 多条件连接已支持并且/或者（AND 优先结合）；是否需要括号分组（当前判断不需要，复杂逻辑归正则）。
- 筛选是否随地址栏往返（后退/前进）恢复——`DirectoryFilterAddress` 已具备编码能力，建议随导航历史走。
