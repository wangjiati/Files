全视图筛选 · 交互设计说明

面向重度资源管理器用户：效率、组合性、信息密度优先。名称维度完全内联（零弹层）；全部维度是可重复添加、带并且/或者连接符的展开式条件控件组——即时编辑、即时生效，不再收起成摘要药丸；“搜索子文件夹”仅在筛选生效时参与匹配。画布上的编号圆点对应下列章节，全部流程可点击试用。

1 · 统一入口：工具栏漏斗按钮

沿用现有 ToggleFilterButton（访问键 F，增设 Ctrl+Shift+F）。点按显示/隐藏筛选栏；筛选生效时按钮保持点亮；收起但筛选仍生效时，按钮右上出现活动圆点（与列头 FilterActiveDot 同一语言）。

映射：Toolbar.xaml 的 AppBarToggleButton（FilterHeader）→ 增加“筛选生效”指示。

2 · 常规/高级切换 + 单行统一表达式

筛选栏最前是 [常规 | 高级] 分段切换：常规 = 纯搜索框——名称框支持多关键字（空格或逗号分隔，需同时满足）与 Windows 通配符（* 任意串、? 单字符，整名匹配、忽略大小写），没有“添加”与条件列表（高级设置的条件下不参与常规求值）；高级 = 完整能力（12 个运算符、取反、连接符、正则作用域）。两套配置互不丢失，切回高级即恢复。

名称条件与全部追加条件在同一行内流动，共用完全相同的一套控件（30px 高、13px 字号、同款边框/开关/移除按钮）：[维度名][Aa][.*][.ext][运算符▾][输入框][×]。追加的“名称”条件同样具备这三个开关（高级）；其余维度为 [维度名][运算符▾][值控件][×]。整行宽度用满后才在条件边界换行，＋添加 始终贴住最后一个条件。

映射：ModernShellPage.xaml 的 FilterHeader 行；VS Code 检索栏先例。

3 · 添加筛选 = 追加条件控件组（草稿即聚焦）

菜单顶部选择连接符 [并且添加 | 或者添加]，每次点击新增一条独立条件控件组（七个维度任选、同维度可重复），入列即为可编辑草稿并自动聚焦首个控件（选择类自动弹值选择器）。菜单里已添加的维度显示 ×N 计数。求值：AND 优先结合（A 并且 B 或者 C = (A∧B)∨C）；复杂嵌套逻辑仍归正则。

4 · 条件即控件：形态统一、即时生效

每条条件都是展开的即时编辑控件组，外观与第一个名称条件完全一致：类型 [是▾] ⟨[Word 文档 ×][PNG 图像 ×] ＋⟩（值在输入盒内以令牌呈现，盒式与名称输入框同款）、大小 [1][MB▾]–[100]、修改日期 [最近 1 小时▾]（预设含最近 1/6/24 小时、今天、昨天、最近 3/7/30 天、本月、今年——按当前时间动态计算区间；选“自定义…”就地展开 从/至）、名称 [Aa][.*][.ext][开头是▾][输入框]。全部即时生效，无“应用”按钮；选择类支持 是/不是 取反、令牌单删、超过 5 个折叠 +N；未生效草稿以控件虚线框呈现；每条追加条件（含第一条）始终带 并且/或者 连接符——暂无可连接的前置条件时呈弱化态，填入名称后即刻生效；点击切换、同维度多条自动编号。

5 · 匹配计数与一键清除

右侧实时 “N 个匹配项”；任意筛选生效时出现 清除所有筛选（含名称主条件与全部 chip；递归开关为作用域，保持不动）。零匹配时内容区空态 + 同款清除按钮。状态栏显示“已显示 N / M”。

6 · 值选择器：多选即时，编辑 Flyout 退役

类型/扩展名/标签经条件组内的 ＋ 打开复选选择器：勾选即时生效且保持打开（连续多选），选中值回显为条件组内令牌；标签的选择器尾部提供“包含没有值的项目”。原 DirectoryFilterFlyout 的“应用/清除”流程退役——所有编辑都在内联控件上即时完成，列头入口=追加同名条件草稿。

映射：内联条件控件直绑 DirectoryFilterViewModel（属性即筛选状态）；选择器复用其选项构建逻辑；新增 choice 取反（是/不是）需引擎扩展。

7 · 列头 = 与筛选栏同一套条件

详细视图每个列头漏斗都追加同维度的条件控件组（与「添加」菜单产出的完全一致）：名称列头追加的名称条件具备与筛选栏相同的完整算法——Aa/.*/.ext 三开关与 12 个运算符（含长度类）；类型/日期/大小/标签列头同理。列头激活圆点与条件增删双向同步；常规模式下点击列头自动切到高级并追加条件（列筛选即高级算法）。

8 · 跨视图持久 + 递归子文件夹（防爆炸）

切换 5 种视图筛选不丢。“搜索子文件夹”是筛选的匹配范围，不是显示方式：仅在筛选生效时把子目录项目纳入匹配——未筛选时勾选不改变当前文件夹视图，避免“勾选即全量平铺”的递归爆炸。递归深度默认 2 层、可调（1/2/3/5/不限），常规与高级模式共用；生效时详细视图自动出现“位置”列，卡片副行与其余视图 tooltip 显示相对路径，状态栏附“（含 N 层子文件夹）”；列视图按栏浏览、不递归。

映射：引擎需惰性递归枚举（进度可见、可取消）与每项相对路径来源；原型为两层样例数据。

设计决策与开放问题

决策（可推翻）：⓪ 人设=重度用户；① 原 FilesAndFoldersFilter 并入名称维度；② 名称完全内联、单一关键字/短语；③ Aa=区分大小写、.ext=作用域，三开关同族，文本/正则通用；④ 条件列表 + 并且/或者连接符：AND 优先结合，同维度可重复；⑤ 扩展名独立成维度；⑥ 搜索子文件夹为作用域开关（仅筛选生效时参与），清除筛选时保持；⑦ 空态文案“没有与筛选条件匹配的项”；⑧ 条件为展开控件组、全部即时生效（无应用按钮、无药丸摘要）；⑨ 选择类支持 是/不是 取反（需引擎扩展）；⑩ 常规/高级切换（默认常规）：常规=纯搜索框（多关键字空格/逗号分隔 + Windows 通配符 * ?，无添加/条件），高级=完整能力，两套配置互不丢失；递归深度默认 2 层可调（常规/高级共用）。
开放问题：列视图递归语义（建议不递归）；递归结果的分组/排序策略；地址栏是否编码递归状态；括号分组 UI（当前判断：不需要，复杂逻辑归正则）。
